## One question to take away

**What would GitHub Copilot modernisation unlock for your team?**

## The main lesson

Combine structured knowledge, autonomous execution, validation, learning and deliberate human decision points into one connected system. Each piece on its own is useful. Together they make modernisation repeatable and trustworthy.

## Ways to start

- **Stocktake first.** Record each legacy system's product and version, support status, ownership, exposure and dependencies. See [Three questions](three-questions.md).
- **Pick one system and find its safe step.** Check how much of a regression net it has before you change it. See [Two assumptions](two-assumptions.md).
- **Write down your goals.** Add repository custom instructions and an `AGENTS.md` so agents know your conventions.
- **Run an assessment.** Try GitHub Copilot modernization on a single application and read the plan it writes into your repository.
- **Capture what you learn as a skill.** Turn a migration pattern that worked into a reusable skill for the team.
- **Measure.** Turn on Copilot usage metrics and the audit log so you can show evidence, not just anecdotes.
