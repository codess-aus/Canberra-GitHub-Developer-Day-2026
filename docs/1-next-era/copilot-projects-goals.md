## Organise work around an outcome

The screenshot shows a project overview with work grouped by status. The project keeps a broader goal, its supporting context, parallel agent sessions and resulting pull requests together. Instead of launching and tracking every task separately, you can follow progress and step in when the work needs a decision.

GitHub Docs describes Projects as an ongoing goal that can span one or more repositories, or work that does not need a repository. Projects can include supporting files and other context, and can coordinate sessions, recurring tasks and generated artefacts. A focused project goal helps keep the work and results related.

Use a project when the work crosses tasks or repositories. For a discrete task in one repository, GitHub recommends starting an agent session directly from that repository. Copilot Projects is in public preview, so its behaviour and interface may change.

For the related product story, see [More complex work: Copilot Projects](copilot-projects.md).
