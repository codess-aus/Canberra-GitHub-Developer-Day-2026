Presented by **Scott Holden**, Senior Solution Engineering Manager, Microsoft.

Security needs to keep pace with both faster software delivery and faster exploitation. This chapter follows a practical path: find and fix existing risk, prevent new risk entering code and dependencies, and make the secure path the default for developers and agents.

The examples cover GitHub and Azure DevOps, from repository scanning and pull request gates to runtime context, identity and agent governance. Controls and availability vary by product, plan and platform; follow the linked documentation before enabling them.

## The route through the session

1. [Security at AI speed](security-at-ai-speed.md), [vulnerability trends](vulnerabilities-and-exploitation.md), and [five questions for leaders](five-questions-for-leaders.md) explain the pressure and the decisions it creates.
2. [GitHub Advanced Security](github-advanced-security.md), [security configurations](security-configurations.md), scanning and [remediation at scale](remediate-at-scale.md) address the existing backlog.
3. [Security across the lifecycle](security-across-the-lifecycle.md), [supply chain protection](secure-the-supply-chain.md), and pull request gates show how to prevent new risk on GitHub and Azure DevOps.
4. [Secure by default](secure-by-default.md), [agent governance](govern-ai-agents.md), modernisation and [five actions](five-actions.md) turn the ideas into an operating model.
