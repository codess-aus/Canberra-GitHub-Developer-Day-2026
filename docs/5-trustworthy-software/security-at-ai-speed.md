    Security has to move at the speed of AI.

## A faster development loop needs faster feedback

AI helps developers and agents produce and change software more quickly. Attackers can use AI too, so the time available to discover, prioritise and fix weaknesses can shrink. More output alone does not make software safer: teams still need to understand what changed, what is exposed and whether the fix works.

The answer is a combination of automation and human judgement. Use controls at the stages where they can make a difference: prevent secret exposure at push, review changes before merge, check dependencies at install, and investigate deeper risks in important repositories. The rest of the chapter explains how those layers fit together.
